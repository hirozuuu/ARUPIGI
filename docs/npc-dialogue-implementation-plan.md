# NPCと会話機能の実装計画書

作成日：2026-09-27

状態：計画作成済み。機能の実装・実行検証は未着手。

Godot 4.6.x / GDScript / GL Compatibilityを前提とする。第1節はユーザーと合意した仕様、第2節以降は既存実装を調査したうえでの設計方針とする。今回の成果物はこの計画書であり、ゲーム実装は変更しない。

関連資料：[マップ編集ガイド](map-editor-guide.md)、[マップ編集の実装計画](map-editor-implementation-plan.md)、[マップ編集の検証記録](map-editor-verification.md)、[戦闘表示の実装計画](battle-overlay-implementation-plan.md)。

## 1. 確定した仕様と対象範囲

| 項目 | 確定内容 |
| --- | --- |
| 配置場所 | フィールドや町にNPCを配置できる |
| 配置と移動 | マス単位の固定配置。NPCは歩き回らず、探索中の主人公はNPCをすり抜けられない |
| 話しかけ方 | 主人公が近くのNPCの方を向いてEnterを押す |
| 会話中 | 主人公の移動と敵との遭遇を停止する。Enterで次のページへ進む |
| 本文 | 日本語のみ。自動折り返しと手動改行に対応し、1ページ最大2行。長文は2行ごとにページを分け、ページ単位で一括表示する |
| 名前と選択肢 | 本文の2行には含めず、別枠に表示する |
| 分岐 | 選択肢によって返答や後続の会話が変わる。選択結果は次の会話に持ち越さない |
| 選択操作 | 上下キーで選択、Enterで決定。選択肢数に固定の上限を設けず、画面に収まらない場合はスクロールする |
| 中断 | 会話中のEscは無効。終了まで会話を進める |
| 編集 | 既存の「マップ」エディタでNPCを配置・選択し、専用パネルで名前・見た目・本文・選択肢・分岐先を編集する |
| プレビュー | 本文の2行表示と、選択肢を操作して分岐を試せる会話プレビューを用意する |
| 仮グラフィック | 既存の絵に合わせたシンプルな人型。色で区別できる |

会話をまたぐ選択の記憶、次回の会話の変更、進行フラグ、条件による会話の出し分け、回復・アイテム・イベント等の効果は実装しない。編集パネルにも「会話の条件」は設けない。話しかけるたびに同じ開始位置から会話を始める。

翻訳、音声、顔グラフィック、文字送り演出、NPCの自律移動、セーブ、新規マップ作成、実行中ゲームへの編集の即時反映、Windowsビルドの作成・検証は対象外とする。

## 2. 現状と変更の要点

| 既存箇所 | 現状 | 変更方針 |
| --- | --- | --- |
| `scripts/main.gd` | 探索・メニュー・遷移・戦闘の状態と入力を管理 | 会話状態を追加し、開始・ページ送り・選択・終了を管理 |
| `scripts/exploration.gd` | 主人公・マップ・カメラ・戦闘枠を管理 | NPCの生成・破棄、話しかける対象の検索を追加 |
| `scripts/player.gd` | 足元の円で衝突。実際に移動できたときだけ向きを更新 | 壁やNPCに接していても、方向入力で会話に使う向きを更新 |
| `scripts/map_controller.gd` | 地形と目印を描画し、地形衝突を生成 | 地形処理を維持。NPCの身体・会話処理は専用クラスへ分離 |
| `scripts/data/map_data.gd` | 地形・出入口等をResourceで保持 | 空配列を既定値とするNPC一覧を追加 |
| `scripts/game_ui.gd` | 通知・メニュー・戦闘UIを描画 | 会話専用表示を組み込み、通常の画面下部の案内と重ならないようにする |
| `addons/map_editor/map_edit_document.gd` | 地形を複製し、地形のみのスナップショットで履歴・未保存判定 | NPCと入れ子の会話も編集用に複製し、履歴・比較・保存に含める |
| `addons/map_editor/map_editor_panel.gd` / `map_canvas.gd` | 地形配置、検証、保存、復旧 | 地形／NPCの編集モード、NPC詳細、会話編集とプレビューを追加 |
| `scripts/data/map_validator.gd` | 形式と重要地点への到達性を検証 | NPC配置と会話構造を検証。NPCによる動線への影響も警告 |

現状の`copy_map()`は地形等のコンテナーを複製し、`_snapshot()`は`rows`と`terrains`だけを比較する。NPC一覧を追加するだけでは入れ子の会話が共有され、履歴や未保存判定も成立しないため、編集データの分離を最初に実装する。

以下ではNPCを既存のMapDataに追加し、洞窟でも利用できる共通の仕組みとする。衝突形状・会話距離・具体的な画面構成は実装上の初期案であり、ユーザー指定の数値ではない。確定仕様と受け入れ条件を保った範囲で、実装・描画確認に応じて調整する。

## 3. データ設計

### 3.1 保存単位

`MapData.npcs: Array[NpcData]`を追加する。NPCと会話はマップ内のサブResourceとして保存し、既存のマップ1ファイルの保存・復旧に含める。NPCの画像は外部Texture2Dを参照する。

この段階では会話を独立した外部ファイルとして共有しない。NPCの複製時は会話も独立したコピーにする。これにより、複数ファイルの同時保存や、1人の会話編集が他のNPCへ波及する操作を避ける。

### 3.2 Resourceの構成案

| Resource | 主なフィールド | 用途 |
| --- | --- | --- |
| `NpcData` | `id`、`display_name`、`cell`、`texture`、`tint`、`dialogue` | マップ内で一意のID、名前、セル座標、見た目、会話 |
| `DialogueData` | `start_node_id`、`nodes: Array[DialogueNodeData]` | 会話の開始位置と本文の一覧 |
| `DialogueNodeData` | `id`、`editor_label`、`text`、`next_node_id`、`choices: Array[DialogueChoiceData]` | 1まとまりの本文と、その後の進み方 |
| `DialogueChoiceData` | `text`、`next_node_id` | 選択肢の表示文と移動先 |

エディタから利用するデータクラスは`@tool`とする。名前は表示専用、IDは参照専用として分離し、通常の編集ではIDを自動生成する。表示名の変更や一覧の並べ替えで参照先を変えない。

「会話ノード」は編集上の本文1件を意味し、Godotのシーンノードとは別のResourceとする。1件の本文は長文を保持でき、実際の2行ページは表示時に生成する。

### 3.3 会話の接続ルール

- 選択肢がない本文は、最終ページでEnterを押すと`next_node_id`へ進む。空の移動先は会話終了を意味する。
- 選択肢がある本文は、最終ページで選択肢を表示する。選んだ項目の移動先へ進み、空なら終了する。この場合、本文側の`next_node_id`は空とする。
- 選択肢を選ぶ前に後続処理や結果の確定をしない。
- 共通の返答への合流や、質問一覧へ戻る分岐を許可する。入力なしで接続を自動的にたどらず、循環による処理の無限ループを防ぐ。
- 開始位置から到達可能な各本文について、少なくとも1つの終了経路があることを検証する。Escが無効のため、終了経路のない循環は保存不可とする。
- 会話の実行状態はResourceへ書き込まず、会話を終えると破棄する。再度話しかけると開始本文から再生する。

### 3.4 分岐会話の作成例

| 本文の編集用ラベル | 本文 | 選択肢または次の移動先 |
| --- | --- | --- |
| 案内（開始） | 「何を知りたいですか？」 | 「町について」→町の返答、「洞窟について」→洞窟の返答、「もう大丈夫」→会話終了 |
| 町の返答 | 「町の北には、休める泉があります。」 | 案内へ戻る |
| 洞窟の返答 | 「洞窟へ行くなら、準備を忘れずに。」 | 会話終了 |

同じ会話中に別の質問を選べるが、質問済みの印や次回用の記憶は残さない。この例で分岐、戻り先、終了経路、再会話のリセットを確認する。

## 4. ゲーム内の動作

### 4.1 配置・衝突・描画

NPCの足元をセル中央に置き、シンプルな人型SVGを足元に合わせて表示する。仮画像は既存の48×48の人物素材と整合する大きさにし、色変更は服などの色を識別しやすいことを確認する。移動・歩行アニメーションは用意しない。

衝突は足元の小さな固定形状とし、探索用の衝突として主人公を止める。初期案は幅24・高さ18ピクセルとし、接近して話しかけられる距離と見た目を描画検証で調整する。地形の`MapData.is_walkable()`は地形だけの判定として保つ。

主人公とNPCは足元のY座標を基準に描画順をそろえ、奥にいる人物が手前の人物を不自然に覆わないようにする。カメラは既存の主人公追従を維持し、会話開始時に移動やズームを行わない。

マップ切り替えでは前のNPCを破棄して現在のマップのNPCだけを生成する。旧マップに残る衝突や話しかけ対象がないことを検証する。

### 4.2 話しかける対象

- 探索中のEnter押下で、主人公の足元からの距離と向きで候補を絞る。
- 初期値は距離がタイルサイズの1.25倍以内、正規化した向きとの内積が0.5以上とする。候補が複数なら距離、次にNPCのID順で1人に決める。
- 地形や別NPCに遮られた相手には話しかけない。主人公自身と対象NPCの形状を適切に除外して遮蔽を確認する。
- 候補がいるときは「Enter 話す」を表示し、会話相手の名前を確認できるようにする。表示対象と実際にEnterで選ばれる対象は同じ検索処理を使う。
- NPCにぶつかって移動量が0になっても、入力した方向に向ける。斜め方向の移動・会話も扱う。

距離と角度は調整可能な定数にまとめる。近接・斜め・壁越し・複数候補の検証を通したうえで最終値を決める。

### 4.3 状態と入力

`State.DIALOGUE`を追加し、探索からのみ開始する。会話中は探索の移動、出入口、回復地点、遭遇判定、メニュー開始を処理しない。会話開始時に主人公の速度と歩行表示を停止する。

| 状態 | 操作 | 結果 |
| --- | --- | --- |
| 探索・相手あり | Enter | 会話開始、最初のページを表示 |
| 本文の途中ページ | Enter | 次の2行ページ |
| 本文の最終ページ・選択肢なし | Enter | 次の本文または会話終了 |
| 本文の最終ページ・選択肢あり | 上下／W・S | 選択変更。主人公は移動しない |
| 同上 | Enter | 選択肢の移動先へ進む、または終了 |
| 会話中 | Esc | 何もしない |

既存の`confirm_armed`による解放待ちとキーリピート抑止を会話にも適用する。開始のEnterで最初のページを飛ばさず、最終ページへ進めたEnterで選択まで決定しない。終了のEnterで即座に話しかけ直すことも防ぐ。

会話が終わったら同じ位置・HP・カメラ位置で探索に戻る。遭遇までの累積距離は保持し、会話だけで距離を加算・リセットしない。会話の開始判定が成立したフレーム以降は遭遇処理に入らない。

### 4.4 戦闘との整合

既存の戦闘中の移動は戦闘用衝突レイヤーだけを利用するため、NPCを戦闘の障害物に追加しない。戦闘中の会話開始は無効とし、NPCは背景の一部として表示する。

戦闘終了位置がNPCと重なっている場合は、そのNPCに限り一時的に主人公との衝突を除外し、重なりを抜けた時点で復帰させる。戦闘終了時の座標維持と、重なりから脱出できることを両立する。重なっていないNPCの衝突は通常どおり有効にする。マップ移動・敗北時には除外状態を破棄する。

## 5. 本文と選択肢の表示

会話表示用の共通Controlと、日本語の行分割・ページ分割を行う補助クラスを用意する。ゲームとエディタのプレビューは同じフォント・文字サイズ・本文幅・分割処理を使う。

- 基準画面960×640の下部に会話枠を置く。名前は本文とは別の見出し枠とする。
- 本文は実際のフォントの描画幅から折り返し位置を求める。固定文字数による分割にはしない。
- 明示的な改行を保持し、表示行を最大2行ずつページにまとめる。入力欄自体は2行に制限しない。
- 句読点や閉じ括弧が行頭に来る場合など、日本語の禁則処理を考慮する。長い連続文字列も枠内で分割し、行幅を超えさせない。
- 末尾の不要な改ページを作らない。空白だけの本文は保存時に検出する。
- ページ数と進行案内は本文とは別に表示する。文字送りは行わない。
- 選択肢は本文の最終ページに到達してから別枠に表示する。最初の項目を初期選択とする。
- 選択項目が常に見えるよう一覧をスクロールする。上下端では選択を止め、長い選択肢は折り返す。1項目が表示領域より長い場合も全文を確認できるスクロール手段を設ける。
- 選択肢の枠は本文・名前・操作案内を覆わない。960×640を基準に既存の等方拡縮を使い、ウィンドウサイズで本文のページ分割を変えない。

名前や長い選択肢も含め、最小ウィンドウ720×480、横長1200×700、縦長720×900で欠け・重なり・文字化けを確認する。

## 6. マップエディタの拡張

### 6.1 NPCを配置する

上部に「地形／NPC」のモード切り替えを追加する。NPCモードでは一覧、新規作成、選択、移動、複製、削除を提供する。地形の操作とNPCの操作を混同しない表示にする。

1. 「NPC追加」で名前・仮画像・最小の会話を持つNPCを用意し、配置先セルをクリックする。
2. 既存NPCをクリックするか一覧で選択し、詳細パネルを開く。
3. 移動操作で別セルへ置く。名前・色・画像・会話を編集する。
4. 複製ではNPCのIDを新しくし、会話を独立複製して配置先を選ぶ。
5. 削除は地形を変更しない。削除を含む全操作をUndoで戻せる。

新規配置・移動時には範囲外、通行不可、他NPC、出現位置、出入口、回復地点との重複を拒否して理由を表示する。後から地形を編集してNPCの位置を通行不可にした場合などは検証で警告する。

拡縮・スクロール後もセルと表示が一致するよう、既存キャンバスの座標変換を利用する。NPCモードの消去はNPCだけ、地形モードの消去は地形だけに作用する。

### 6.2 会話を編集する

専用パネルは「本文一覧」「選択中の本文」「表示プレビュー」で構成する。初期版では線を引くグラフエディタを設けず、一覧と選択式の移動先で分岐を作る。

- 本文の追加・複製・削除・並べ替え、開始本文の指定。
- 日本語の複数行入力。本文の編集用ラベルと本文先頭を一覧に表示。
- 選択肢の追加・削除・並べ替え、文言と移動先の指定。
- 移動先は本文の一覧または「会話終了」から選ぶ。IDを手入力せず編集できる。
- 参照されている本文の削除は、参照元を示して削除を止める。移動先を変更した後に削除できる。
- 選択肢を追加して進行方式を切り替える場合は、本文側の通常の移動先を整理する操作も同じUndo単位に含める。
- 本文の表示プレビューでは全ページを確認できる。会話プレビューでは開始からの再生・選択・終了・やり直しができる。
- 会話プレビューには編集用の「停止」ボタンを設ける。ゲーム内のEsc無効とは独立して停止でき、編集中の終了経路が不完全でも編集へ戻れる。構造エラーがある場合は開始前に対象箇所を示す。
- 会話プレビューは編集中のコピーを使い、プレビューの進行でデータ・未保存状態・履歴を変更しない。編集後に再生し直せば変更が反映される。

### 6.3 日本語入力と履歴

文字入力欄にフォーカスがある間は、その欄の文字編集とIME変換を優先する。Enterを会話プレビューの決定や本文編集の確定として誤処理しない。

IMEで確定済みの本文は作業データへ反映し、短い入力のまとまりを1回のUndoにまとめる。フォーカス移動・保存・NPC切り替え・マップ切り替え・プラグイン終了前には、保留している履歴のまとまりを確定する。ここでの確定はドキュメントへの反映を意味し、IMEの変換候補を自動決定することではない。IME変換中の未確定文字は保存データに混ぜず、確定済み文字までを保持する。

地形・NPC配置・会話編集は同じドキュメントの履歴で扱う。文字入力中のCtrl+Zは文字編集を優先し、入力欄を離れた後のUndo／Redoでは確定した編集単位を戻す。入力欄のローカル履歴とドキュメントの状態が食い違わないよう、復元時に表示を同期する。

## 7. 保存・互換性・復旧

- `npcs`のない既存マップと既存復旧データは、NPCなしとして読み込めるようにする。既存マップを一括変換しない。
- NPC・会話・選択肢のResourceと配列を明示的に複製し、画像・地形・敵の外部Resource参照を維持する。単に配列を複製して入れ子を共有する実装にはしない。
- スナップショットは入れ子の値まで独立して保持する。未保存判定にはResourceのインスタンス同一性ではなく内容の比較を使う。
- NPC編集後に保存前の共有Resourceや他NPCが変化していないことを確認する。
- 既存の一時ファイル保存、再読み込み照合、外部変更検知、元UIDの維持、同一ディレクトリでの置き換えを拡張して使用する。
- 保存照合にはNPC・本文・選択肢・分岐先・画像参照も含める。保存後の再編集を外部変更として誤検知しないことを確認する。
- 保存失敗時は作業内容と履歴を保持する。保存後もUndoでき、保存時と同じ内容に戻れば未保存表示が解除される。
- 復旧データにもNPCと会話を含め、入力が確定した変更をチェックポイントへ反映する。構造を編集している途中のデータも復旧側には保持し、正式保存の検証とは分ける。
- NPC・会話に修正可能なエラーがあっても詳細パネルを開いて修正できるようにする。地形の構造破損による描画停止と、会話の検証エラーを区別する。
- プラグインの保存フック、未保存通知、無効化・再有効化後の復旧にも反映する。既存のユーザー復旧データをテスト都合で削除しない。

## 8. データの検証と異常時の動作

| 検証内容 | 扱い |
| --- | --- |
| NPCまたは会話Resourceが欠落、NPCのIDが空・重複 | 保存不可。対象を特定して修正できるようにする |
| 本文のIDが空・重複、開始位置・移動先が存在しない | 保存不可 |
| 名前・本文・選択肢の表示文が空白のみ、仮画像も含め画像がない | 保存不可 |
| 本文に通常の移動先と選択肢が両方設定されている | 保存不可 |
| 開始から到達する本文に終了経路がない | 保存不可 |
| 使われていない本文 | 警告して保存可 |
| NPCが範囲外・通行不可・他NPCや重要地点と重複 | 警告して保存可。通常の配置UIでは事前に拒否 |
| NPCに話しかける隣接位置へ到達できない | 警告して保存可 |
| NPCによって重要地点への通路が塞がる可能性がある | 警告して保存可 |

動線検証は既存の4近傍セル探索を拡張し、NPCのセルを占有セルとして扱う保守的な警告とする。足元の衝突はセル全体より小さいため、実際には通れる隙間を警告する可能性がある。実際の到達性と話しかけ距離はゲーム統合検証でも確認する。

正式なサンプルマップは警告も解消する。編集中のマップの警告を許すことと、ゲームへの採用条件を区別する。

実行時も会話開始前に構造を確認する。手動編集などによる無効なデータに遭遇した場合は理由をログへ出し、探索を停止したままにしない。途中で移動先が見つからない場合も安全に会話を終了する。範囲外・通行不可・重複する配置は理由とNPCのIDをログへ出して生成を省略し、勝手に別座標へ移して保存しない。NPC同士が重複する場合はID順で先の有効な1体を採用する。到達性だけの警告は生成省略の理由にしない。

## 10. 実装順序と完了条件

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| 1. データと検証 | Resource、会話進行モデル、構造検証、編集用複製 | 分岐・合流・終了・再会話と、入れ子データの独立性を検証できる |
| 2. NPCと接触 | 固定配置、仮画像、衝突、向き、対象検索 | 野原・町で正しい相手にだけ話しかけられる |
| 3. 会話表示 | 2行ページ、名前、選択肢、状態と入力の接続 | 長文と分岐会話が最後まで進み、探索に戻れる |
| 4. 編集とプレビュー | NPC編集、本文と分岐の編集、表示・会話プレビュー | コードやResourceの手編集なしでNPCと分岐会話を作れる |
| 5. 保存と復旧 | 全編集の履歴、比較、保存、復旧、保存フック | 保存・再読み込み・Undo／Redo・再有効化で会話を失わない |
| 6. サンプルと通し検証 | 既存マップへ配置、統合・描画・操作確認、文書更新 | 第11節を満たし、作成からゲーム内会話まで再現できる |

第1段階から保存・履歴用のデータ構造を用意し、第5段階で失敗経路とプラグイン連携まで検証する。機能だけでなく、会話を容易に編集して安全に保存できることまでを完成範囲とする。

### 11.3 実行環境とコマンド

実装後、クラス・素材の追加に伴うheadlessインポートを先に実行する。以下は新規テストの作成後に使う予定のコマンドであり、計画書作成時点では実行しない。

$godotExe = 'C:/Program Files/Godot/Godot_v4.6.2-stable_win64_console.exe'

既知の証明書ストア・ユーザーフォルダーへの設定保存のエラーは、テストのPASS／FAIL・終了コード・スクリプトエラーと区別する。Windowsビルドの作成・実行ファイルの検証は行わない。

### 11.4 受け入れ条件

1. マップエディタだけで野原・町にNPCを置き、名前・外見・文章・選択肢・分岐を作成できる。
2. 保存してゲームを再起動すると配置が反映され、近くで相手を向いてEnterを押すと会話できる。
3. 本文は常に最大2行で、長文を欠落なく読み進められる。名前・選択肢は本文の行数に含まれない。
4. 選択肢によって別の返答に進み、会話を終了できる。再び話しかけると開始本文に戻る。
5. 会話中は主人公が動かず、敵に遭遇しない。会話終了後は探索を続けられる。
6. NPCと会話の編集をUndo／Redoでき、保存・復旧後にも配置と分岐が一致する。
7. プレビューとゲームのページ分割・選択結果が一致し、日本語を作成・編集できる。
8. 既存の移動・地形編集・町と洞窟への移動・回復・戦闘が回帰検証を通る。
