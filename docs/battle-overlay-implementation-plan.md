# フィールドに重ねる戦闘表示の実装計画書

作成日：2026-09-27

追加仕様（2026-09-27）：逃走は確率判定から枠外への移動に変更した。「にげる」決定後、`escape_seconds`（初期値1.3秒）の間だけ外枠の線・衝突を解除し、主人公の画像全体が外へ出れば成功する。時間切れは画像と足元を枠内へ戻し、外枠を復活させて1回反撃を受け、次のコマンド選択または敗北結果へ進む。成功時も外枠を復活させ、結果のEnter確認で探索へ戻る。本書の枠内移動・逃走率・戦闘計算維持に関する記述より、この追加仕様を優先する。

状態：2026-09-27に実装・自動検証済み。実キーボードでの手動確認は実行環境のウィンドウフォーカス制約により未完了。検証結果は[検証記録](verification.md)を参照。

同日の実装レビューで、敵名を枠外へ移し、リサイズをGodot標準の等方拡縮へ統一した。第3節にはこの実装結果を反映している。

本書は[初期プロトタイプ実装計画書](implementation-plan.md)に対する追加開発計画である。戦闘表示、戦闘中の移動・入力、勝利・逃走後の位置については本書を優先する。第1節はユーザーと合意した仕様、第2節以降は実装方針と検証計画とする。

## 1. 確定した仕様

### 1.1 表示と配置

- フィールドを表示したまま、その上に戦闘の枠・敵・コマンドを重ねる。
- 戦闘開始時に主人公を作り直したり別の場所へ移したりせず、マップ座標、画面上の位置、表示サイズを完全に維持する。
- 戦闘開始時のカメラ位置を固定し、戦闘中は主人公を追従しない。フィールドからそのまま戦闘へ移ったように見せる。
- 主人公と敵がいる戦闘枠は正方形とする。基準画面960×640では、上側・左右中央に400×400で配置する。
- 戦闘枠の内側はフィールドがそのまま見えるようにし、枠の外側の背景は少し暗くする。
- コマンド枠は戦闘枠とは独立させて下側に置く。その右側にメッセージ枠を並べる。
- 敵は1体。戦闘枠の上寄りで主人公と重ならない位置に固定配置し、自分では移動しない。
- 敵は96×96程度で表示し、同じ大きさの正方形の当たり判定を持つ。当たり判定を表す線は表示しない。

### 1.2 移動と衝突

- 主人公は戦闘中、常に枠内で自由に移動できる。コマンド選択中、攻撃・反撃などの途中メッセージ中、勝利・逃走・敗北の結果表示中も含む。
- 移動キー、速度、方向はフィールドと同じ。WASD／矢印キーによる連続移動と8方向入力を維持し、斜め移動で速度が増えないようにする。現設定の速度は192ピクセル／秒。
- 主人公の当たり判定は現在の足元の小さな円を使う。現実装の半径9を維持し、絵全体を覆う判定に変更しない。
- 足元の円は戦闘枠の境界や敵の正方形を通過できない。絵が多少敵に重なることや、絵の一部が枠線を越えることは許容する。
- 戦闘中の障害物は戦闘枠の境界と敵だけとする。背景の山・壁・水などの通行可否とマップ外周の衝突は移動を妨げない。
- 戦闘中は出入口、回復地点、再遭遇を発動させず、戦闘で歩いた距離を遭遇抽選に加算しない。

### 1.3 入力と戦闘ルール

- 方向キー入力は、連続的な主人公移動と離散的なコマンド選択の両方に使う。
- コマンド選択中に上／下またはW／Sを押すと、主人公がその方向へ移動し、同時に「こうげき／にげる」の選択が1回切り替わる。
- 押し続けている間は移動を続ける。OSのキーリピートで選択を繰り返し切り替えない。左右またはA／Dは移動だけを行う。
- 途中メッセージ中と結果表示中の方向入力は移動のみに使い、コマンド選択は変更しない。結果表示中のEnterは、従来どおり戦闘終了の操作として受け付ける。
- Enterによる行動決定・結果画面からの復帰、途中メッセージの自動進行、決定キーの持ち越し防止、戦闘中のEsc無効を維持する。
- 主人公と敵の位置・距離は攻撃可否、命中、ダメージ、逃走率に影響しない。接触による追加ダメージはない。
- 既存の1対1のコマンド戦闘、HP、攻撃・反撃・逃走・勝敗の計算は維持する。

### 1.4 戦闘終了と既知の制約

- 勝利・逃走後は同じマップの**戦闘終了時の主人公座標**を引き継ぐ。開始時の座標へ戻さない。
- 終了時とは最終結果をEnterで閉じた時点とする。勝敗が決まった後、結果表示中に動いた分も引き継ぐ。
- HPを保持し、遭遇距離をリセットして既存の安全距離を設定する。カメラは終了時のワールド座標を保ち、探索中の移動に合わせて追従位置へ戻す。
- 敗北時は例外として従来どおり町の回復地点へ移動し、HPを全回復する。敗北の結果表示中も移動できるが、その座標は帰還先にしない。
- 山・壁など、本来通行不可の場所やマップ外で戦闘を終了することを許容する。帰還先の通行可否チェック、近傍の安全地点への移動、開始位置への巻き戻し、マップ内への座標制限は追加しない。
- 探索へ戻った後は通常の地形衝突を再び有効にする。障害物内からの移動不能や物理エンジンによる押し出しなどは起こり得る。これを根本的に解決する別仕様は将来の対象であり、今回の実装には含めない。
- 出入口・回復地点の上で終了した場合は、探索再開後の通常の更新で判定する。戦闘中には発動させない。

## 3. 実装設計

### 3.1 主人公と座標を共有する

探索で使用している `Player` を戦闘中も継続使用する。別の主人公を重ねたり、フィールド上の主人公を非表示にしてUI内へ複製したりしない。戦闘開始直前の座標を保持し、開始処理で位置・向き・歩行アニメーションを不必要にリセットしない。

戦闘中も主人公の現在位置を `GameSession.position` に反映する。ただし、探索専用の出入口・回復・遭遇処理は実行しない。戦闘中の位置更新と探索イベントの更新を分ける。

カメラの固定は追従処理から独立させる。現在のカメラが主人公の子であることに注意し、単に追従用コードを止めるだけでなく、主人公が動いてもカメラのワールド位置が変わらない構成にする。切り替え前後で実際の画面変換を確認し、開始フレームでスクロールが跳ねないようにする。

### 3.2 枠の見た目と物理境界を一致させる

基準画面での実装済みの配置は以下とする。

| 要素 | 基準座標・サイズ |
| --- | --- |
| 戦闘枠 | 左上 `(280, 20)`、サイズ `(400, 400)` |
| 主人公 | 探索から引き継ぐ。通常の追従状態では足元が画面中央 `(480, 320)` |
| 敵 | 中心を概ね `(480, 150)`、表示と衝突を96×96とする |
| コマンド枠 | 左上 `(28, 440)`、サイズ `(272, 172)` |
| メッセージ枠 | 左上 `(319, 440)`、サイズ `(613, 172)` |
| 主人公HP | 戦闘枠の左側の余白を利用する |
| 敵名 | 枠外右上 `(704, 24)`、サイズ `(228, 75)` のパネルに配置し、敵の上側へ移動した主人公とも重ねない |

実際の文字サイズと余白は描画確認で調整する。戦闘枠の下端と下側の枠の間には隙間を設ける。

戦闘範囲は1か所で定義し、UI描画と物理境界が同じ範囲を参照する。画面座標の値をそのままワールド座標として扱わず、カメラとCanvasの変換を使って相互変換する。境界には4辺の静的な衝突形状を置き、円が内側に収まるようにする。

`project.godot` の `canvas_items` と `window/stretch/aspect="keep"` により、論理画面は常に960×640とし、フィールド・主人公・敵・UIをGodotが一括で等方的に拡縮する。異なる縦横比では余白が生じる。戦闘用に別の倍率やカメラのリサイズ補正を持たない。

戦闘開始時に確定した枠・敵・主人公のワールド座標とカメラ倍率は、同じ戦闘中のリサイズでは変更しない。開始時には探索と同じ表示変換を引き継ぐ。検証では論理座標の正方形だけでなく、ウィンドウのストレッチ変換を適用した枠・敵のサイズと、敵画像・衝突形状の一致も確認する。

### 3.3 衝突と描画の切り替え

- 地形用と戦闘用の衝突レイヤーを分け、主人公のマスクを戦闘開始・終了で切り替える。元の設定を保存し、終了時に確実に復元する。
- 戦闘用の境界と敵の衝突は戦闘中だけ有効にする。勝利・逃走・敗北の全経路で無効化し、次の戦闘に残さない。
- 敵の表示矩形と正方形の衝突形状を共通の位置・サイズから作る。素材は縦横比を保って矩形に収める。
- 主人公の円と敵の正方形の接触は既存の移動・滑り処理を使う。敵を回り込めるよう、敵と枠の間に十分な余白を設ける。
- 描画順はフィールド、敵・主人公、暗幕と枠線、文字・コマンドの関係を明示し、UIの塗りつぶしで主人公を隠さない。暗幕は戦闘枠の外側だけを覆う。
- 既存の短い敵の点滅を維持する。敵HPが0になっても途中メッセージ中は既存と同様に表示を残し、勝利の結果表示で敵を消す際に衝突も無効化する。見えない障害物を残さない。

### 3.4 連続移動と離散入力を分ける

`_physics_process()` の戦闘分岐で、フェーズに関係なく移動を毎物理フレーム更新する。方向は既存の `Input.get_vector()`、速度は既存の設定、実際の移動は `Player.move_player()` を利用する。

探索・戦闘とも `Exploration.step()` を呼ぶ。出入口・回復・遭遇の処理は `Main` の探索分岐に限定し、戦闘では戻り値の移動距離を遭遇処理へ渡さない。

`_input()` では従来どおり非リピートの押下イベントでコマンドを選ぶ。コマンドに使った方向入力を移動側から取り除かない。壁や敵に阻まれて移動量が0でも、上下キーによる選択切り替えは行えるようにする。

攻撃・逃走を実行できるのは `command` のときだけとし、`busy` で新たな行動を受け付けない。`busy` と `result` でも方向入力は移動に使用する。メニューとマップ遷移で移動を停止する従来の制約は維持する。

### 3.5 終了処理と帰還情報

勝利・逃走の終了処理では、まず主人公の実座標をセッションに確定する。戦闘用の衝突を解除し、探索用の衝突・カメラを戻す。保存した開始位置を復元する処理は実行しない。

`GameSession` の `battle_position`、`save_battle_return()`、`restore_battle_return()` は参照元とテストを確認して整理する。開始時情報を診断に残す場合も、帰還先としては使用しない。古いAPIを残して今回の経路だけ迂回するより、実際に必要な責務に合わせて整理する。

終了時の速度を整理しても、押下中の方向入力自体は消さない。探索再開後は通常の入力状態に従って移動する。終了処理での座標引き継ぎと、その後の通常の物理移動・押し出しは区別して検証する。

敗北でも戦闘用オブジェクト、衝突設定、カメラを確実に片付け、既存の暗転と町への移動を行う。連続した戦闘やシーン再生成で設定が残らないようにする。

勝利・逃走で探索へ戻った瞬間は、戦闘中のカメラのワールド座標と背景の表示位置を保つ。主人公がフィールドで実際に移動した距離に応じてカメラを通常の追従位置へ滑らかに近づけ、最終的に主人公を画面中央へ戻す。停止中はカメラも停止する。

## 4. 実装順序

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| 1. 表示と座標の基盤 | `BattleArena`、共通の範囲計算、カメラ固定、フィールドを残す表示を追加 | 開始時に主人公と背景が跳ねず、通常サイズ・リサイズ時とも正方形が保たれる |
| 2. 衝突と移動 | 地形／戦闘の衝突切り替え、枠の4辺、敵の正方形、全フェーズの移動を実装 | フィールドと同じ速度で動き、地形を無視して枠と敵にだけ止められる |
| 3. UIと同時入力 | 下側のコマンド・メッセージ配置、敵名・HP・点滅、操作説明を更新 | 押下時の選択と押し続けた移動が同時に成立し、全メッセージが読める |
| 4. 終了と復元 | 終了座標の引き継ぎ、敗北処理、カメラ・衝突の復元、帰還APIを整理 | 勝利・逃走で終了座標を保持し、敗北だけ町へ移動する |
| 5. 検証と文書 | ロジック・統合・描画テストを更新して実行し、必要な不具合を修正 | 下記の受け入れ条件を満たし、READMEと検証記録が実装に一致する |

新規スクリプトの追加後はheadlessインポートを行い、Godot 4.6.2で検証する。既存の `.uid` とResource参照は維持し、新規スクリプトに生成される `.uid` も管理する。

## 5. 検証計画

### 5.1 ロジック・統合検証

既存の `logic_test.gd` と `integration_test.gd` を更新する。入力と物理フレームを使い、実際の移動・状態遷移を検証する。

| 分類 | 確認内容 |
| --- | --- |
| 開始時の連続性 | フィールドが可視のままで、主人公のワールド座標・画面上の座標・表示サイズが開始前後で一致する。移動キーを保持したまま遭遇しても跳ねない |
| カメラ | 戦闘中に主人公が移動してもカメラの位置と背景が動かない。終了後は探索の追従に戻る |
| 移動速度 | WASD・矢印の両方で動き、軸方向と斜め方向の同時間の移動距離が同等。探索と同じ設定速度になる |
| 常時移動 | `command`、`busy`、`result` のすべてで移動する。敗北結果でHPが0でも移動する |
| 同時入力 | 上下押下で選択が1回変わり、同時に移動する。保持中は移動だけ継続し、echoで選択が変わらない。左右は選択を変えない |
| 移動を阻まれた入力 | 枠や敵に押し付けた状態でもコマンド選択とEnter決定ができる |
| 枠と敵 | 円が4辺・角・敵の4方向を通過しない。斜め接触で滑り、敵の周りを回れる。撃破後の非表示と衝突解除が一致する |
| 地形と探索イベント | 壁・山・マップ外周の衝突を無視する。出入口や回復地点を踏んでも反応せず、遭遇距離と安全距離を消費しない |
| 戦闘計算 | 攻撃・反撃・逃走成功／失敗・敗北を既存どおり処理し、敵との距離や接触で結果を変えない |
| 勝利・逃走後 | 開始位置と異なる位置へ移動し、結果表示中にも移動して、Enterで閉じた時点の座標とHPを引き継ぐ。安全距離をリセットする |
| 通行不可地点での終了 | 山・壁・マップ外にいる状態でも終了処理が座標を補正しない。通常の物理処理が再開する前の引き継ぎ値を確認する |
| 敗北後 | 戦闘中の位置によらず町の回復地点へ移動し、HPが全回復する |
| 復元と再入場 | 通行可能地点へ戻った場合は探索の地形衝突が通常どおり働く。次の戦闘で以前の境界・敵・カメラ固定が残らない |
| 既存操作 | Enterの押しっぱなし・連打で二重実行や結果の自動消費を起こさない。Escは戦闘中無効。探索メニュー・マップ遷移の停止は維持する |
| リサイズ | 戦闘開始前／戦闘中のサイズ変更で、枠・敵の正方形と見た目に一致する衝突を維持し、主人公のマップ座標をレイアウト都合で変更しない |

帰還テストは「戦闘中に動かず、開始時と同じ位置だった」だけでは成立させない。勝利・逃走とも移動後の座標を明示的に確認する。結果表示中の移動と `busy` の移動は、十分な物理フレームを確保して検証する。

開始時の座標一致は、遭遇判定に至る探索移動を終えた直後と、戦闘開始処理の直後で比較する。開始後の次の物理フレームでは、保持されている方向入力による通常の移動を許容する。終了座標も終了処理の直前・直後で比較し、探索再開後の入力移動や衝突解決を混同しない。浮動小数点の計算誤差には小さな許容差を設けるが、開始・終了の都合による意図的な座標補正は認めない。

### 5.2 描画・操作確認

`render_smoke.gd` を実GPUで実行し、保存画像を目視確認する。画像保存に成功しただけで描画確認完了としない。

- 野原と洞窟で、戦闘直前と直後の画像を比較する。主人公の位置・サイズと背景の連続性を見る。
- 正方形の戦闘枠、透明な内側、外側の暗幕、独立した下側のコマンド枠とメッセージ枠を確認する。
- 敵・主人公・敵名・HP・複数行メッセージが意図せず隠れないことを確認する。
- 主人公が動いた画面、枠・敵への接触、攻撃中、勝利結果、逃走結果、敗北結果を確認する。
- 960×640に加え、現在の最小ウィンドウ720×480、横長の1200×700、縦長の720×900で確認する。保存画像は余白を除いた描画領域を対象とする。
- 実入力で、上下を押してコマンド選択と歩行が同時に発生し、長押しでは選択が繰り返されないことを確認する。

## 6. 完成条件と対象外

第1節の確定仕様を満たし、関連する自動検証が成功し、GPU描画と実入力の確認で主要な表示・操作に問題がないことを完成条件とする。通行不可地形での戦闘終了を許容する既知の制約は、そのまま文書に残す。

敵の自律移動、接触攻撃、距離による戦闘計算、複数敵、新たな攻撃演出、通行不可地点からの救済、将来の地形問題の根本解決、Windows書き出しは今回の対象外とする。
