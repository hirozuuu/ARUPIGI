## 1. 目的と完成条件

Godot 4.6の現在のプロジェクトに、探索・マップ切り替え・ランダムエンカウント・戦闘・回復を一通り遊べるWindows向けのプロトタイプを作る。

昔のドラゴンクエストを参考にしたシンプルな構成とする。ただし、見た目はドット絵にせず、やや落書き風の手描き表現にする。キャラクター、地形、敵、UI素材は独自に作成する。将来の方向転換に備え、地形・マップ・敵のデータとゲームの処理を分離する。

以下の流れを通して操作できることを完成条件とする。

1. 起動直後に野原から探索を開始する。
2. ワールドを自由に歩き、町とダンジョンに出入りする。
3. ワールドまたはダンジョンでランダムに戦闘が発生する。
4. 攻撃で勝利、または逃走して、戦闘前の探索位置へ戻る。
5. 町の回復地点でHPを回復する。敗北時には町へ戻る。
6. メニューでHPと操作説明を確認し、ゲームに戻る。

## 3. 初期版の仮設定

この節の値は実装・試遊のための初期値とし、コードに散在させず、設定またはデータから調整できるようにする。

### 3.1 画面・見た目

- 基準画面サイズは960×640、ウィンドウはリサイズ可能とする。
- タイルの基準サイズは48×48。カメラ倍率はまず固定とする。
- 地形は淡い色面、少し不揃いな輪郭線、草や岩の簡単な描き込みで区別する。
- 平原は緑と草、丘は黄緑と起伏線、砂地は薄い黄土色と点、高山は灰色と尖った山形にする。色だけに依存せず形でも判別可能にする。
- 独自のSVGなどの仮素材を用い、プレイヤーは簡単な手描き風の人型、敵は独自の小動物・岩の生き物などで表現する。
- 素材生成時の線の揺れは固定し、毎フレーム形が変わるちらつきを発生させない。
- 正方形グリッドは地形配置と衝突の基準とし、手描き風の輪郭や模様で見た目を整える。プレイヤー位置はグリッドへ丸めない。
- UIは暗い背景、明るい枠、読みやすい日本語フォント、選択カーソルで構成する。日本語を表示でき、再配布可能なフォントとライセンスを同梱する。
- 移動は向きの変化と軽い歩行表現、戦闘は短い点滅など、必要最小限の演出を付ける。

### 3.2 マップ配置

- ワールド：中央付近を開始地点とし、比較的近い位置に町、少し離れた位置にダンジョンを配置する。
- 平原を主な通路にし、丘・砂地のまとまりと高山の障害物を配置する。開始地点から両方の入口まで必ず到達できるようにする。
- 町：外周の障害物、広場、建物の外観、回復地点、ワールドへの出口を配置する。建物内部への移動は設けない。
- ダンジョン：壁と通路、入口、奥の小部屋を配置する。まず1階層のみとし、ボスや宝箱は設けない。
- 出入口と回復地点は通常の床と明確に見分けられる印を付ける。
- 通行可能な地形による移動速度やエンカウント頻度の違いは、初期版では設けない。

### 3.3 移動・出入口

- 初期移動速度は毎秒4マス相当とする。
- 入力は2次元ベクトルとして受け取り、長さを最大1に制限する。斜め移動を速くせず、将来のアナログ入力では1未満の入力強度も保持できる構成にする。
- 初期版ではアナログスティックの割り当てや実機対応は行わない。キーボード操作で任意角度を指定できるとは扱わない。
- 当たり判定はプレイヤーの足元を表す小さな形状とし、壁沿いに滑らかに移動できるようにする。
- 入口への進入はプレイヤーの基準位置で判定し、絵の端が触れただけで早期に切り替わらないようにする。
- 移動先の出現位置は入口の判定範囲から外し、必要に応じて一度入口から離れるまで再発火を抑制する。
- マップ切り替え中は移動・メニュー・エンカウントを止め、短い暗転を挟む。
- ワールドの端でもカメラを止めず、常にプレイヤー中心を保つ。外側の暗い領域には移動できない。

### 3.4 エンカウント

- 移動前後の実座標から移動距離を計測する。壁へ向かってキーを押し続けるだけでは抽選距離を増やさない。
- 計測対象は探索中の衝突解決後の移動だけとし、マップ切り替え、敗北による移動、戦闘からの復帰などの座標設定は移動距離に含めない。
- マップ側にエンカウント有効フラグと敵の出現候補を持たせる。
- マップ入場・戦闘終了後の最初の4マス分は安全距離とする。
- 新規開始、マップ入場、戦闘終了時は抽選用の蓄積距離をリセットして安全距離を設定する。メニュー開閉では蓄積距離も安全距離も保持する。
- 安全距離の後、1マス分進むごとに約1/16の確率で抽選する。端数の移動距離を保持し、平均約20マス分を初期目安とする。
- 15〜25マス程度は平均頻度の目安であり、毎回この距離範囲に制限するものではない。
- 停止中、メニュー中、マップ遷移中、戦闘中、町では発生しない。
- 同じ更新で入口とエンカウントが成立した場合は、マップ移動を優先する。
- エネミーは戦闘画面に出現し、探索マップ上に歩き回る敵シンボルは配置しない。

### 3.5 戦闘・HP

- 初期値はプレイヤー最大HP30、攻撃ダメージ5〜8を目安とする。
- 仮の敵2種類はHP12／18、攻撃ダメージ2〜4／3〜5程度とする。
- 敵の抽選は、まず各マップの候補から等確率とする。
- 「こうげき」は必ず命中。プレイヤーの攻撃で敵HPが0になれば勝利し、敵は反撃しない。
- 敵が生存している場合は敵が1回攻撃し、プレイヤーが生存していればコマンド選択へ戻る。
- 「にげる」は初期成功率60%。成功時は探索へ戻り、失敗時は敵が1回攻撃する。
- ダメージ、逃走結果、勝敗を短い日本語メッセージで表示する。行動処理中は追加のコマンドを受け付けない。
- 戦闘中のEscで探索メニューを開いたり、戦闘を終了したりできないようにする。
- 勝利・逃走ではHPを保持する。HPが0になった場合は敗北表示後に全回復し、町の回復地点付近へ移動する。
- 回復地点を踏むと全回復し、通知する。上に立っている間は通知を繰り返さない。

### 3.6 画面ごとの操作

| 画面 | 方向キー／WASD | Enter | Esc |
| --- | --- | --- | --- |
| 探索 | 連続移動 | 通常は使用しない。出入口・回復は踏むと発動 | メニューを開く |
| メニュー | 何もしない | ゲームに戻る | ゲームに戻る |
| 戦闘のコマンド選択 | 上下で「こうげき／にげる」を選択 | 選択コマンドを実行 | 何もしない |
| 戦闘結果の表示 | 何もしない | 勝利・逃走・敗北の最終メッセージから探索へ進む | 何もしない |

攻撃・反撃・逃走失敗の途中メッセージは短時間で自動進行し、処理中の入力を無視する。画面や戦闘状態が変わった直後は、決定キーを一度離してから次の決定を受け付ける。

## 4. 構成方針

### 4.1 シーンと責務

| 要素 | 主な責務 |
| --- | --- |
| Main | 起動時の初期化、探索・戦闘・メニューの表示と状態遷移を統括 |
| GameSession | 現在HP、最大HP、現在マップ、探索位置、戦闘からの帰還情報を保持。新規開始時に初期化 |
| Exploration | マップ、プレイヤー、カメラを配置し、探索中だけ更新 |
| MapController | マップデータの読み込み、地形描画、衝突、入口・回復地点を管理 |
| Player | 方向入力、連続移動、衝突、向きと歩行表示 |
| EncounterController | 実移動距離、安全距離、抽選、敵候補の選択 |
| Battle | 敵表示、HP、コマンド、ターン処理、戦闘結果の通知 |
| PauseMenu | HPと操作説明、ゲーム復帰 |

Mainは「探索／メニュー／マップ遷移／戦闘」の状態を明示的に管理し、同時に複数の画面が入力を処理しないようにする。メニュー表示時は探索の移動・アニメーション・エンカウントを停止し、UIだけ操作可能にする。

戦闘開始時には探索のマップと位置を保存し、探索画面の処理を停止する。勝利・逃走時は保存した位置へ復帰し、敗北時のみ町へ移動する。ゲームの起動時にHP、マップ、位置、エンカウント距離をすべて初期化する。

### 4.2 データ

- 地形定義：識別子、表示素材、通行可否。
- マップ定義：識別子、サイズ、タイル配列、開始位置、エンカウント設定、入口、出口、回復地点。
- 出入口定義：判定セル、移動先マップ、移動先の出現地点ID。
- 敵定義：識別子、名前、素材、最大HP、攻撃ダメージ範囲。
- 調整設定：タイルサイズ、移動速度、安全距離、抽選確率、逃走成功率など。

GodotのResource形式を基本とし、マップ共通の処理に個別マップの座標や敵情報を直接埋め込まない。小規模な固定マップとして手作業で配置し、自動生成エディタや独自マップ編集ツールは作らない。

### 4.3 想定ディレクトリ

```text
assets/       手描き風の仮素材、UI、日本語フォントとライセンス
data/         地形、マップ、敵、調整用Resource
scenes/       main、exploration、player、battle、ui
scripts/      状態管理、移動、マップ、エンカウント、戦闘処理
tests/        必要なロジック検証用スクリプト
docs/         計画、起動方法、動作確認手順
```

## 5. 実装順序と各段階の確認

| 段階 | 実装内容 | 完了の確認 |
| --- | --- | --- |
| 1. 起動基盤 | Main、Input Map、日本語フォント、ゲーム状態とセッション | 起動直後から探索でき、日本語が欠けず、初期化できる |
| 2. 探索の基礎 | ワールド地形、連続移動、衝突、中央固定カメラ | 全方向へ移動でき、高山とマップ外に入れず、斜め移動が速くならない |

| 4. 戦闘 | 戦闘画面、敵データ、攻撃、逃走、勝敗、探索への復帰 | 勝利・逃走・失敗・敗北の各経路が成立する |

見た目の最低限の素材は探索段階から用意し、段階6で地形・キャラクター・UIの見た目を揃える。

## 6. 動作確認計画

現段階ではソースをGodotで実行して確認する。Windowsビルドの作成、埋め込みパックの統合・描画検証、書き出した実行ファイルの起動・操作確認は実施しない。将来Windowsビルドを作成する段階で、READMEの将来用手順に従って書き出しとこれらの検証を実施する。

### 6.1 手動の受け入れ確認

- 起動直後に探索でき、終了後の再実行でHP・位置・遭遇距離が初期化される。
- WASDと矢印キーの両方で移動でき、壁沿いの移動や斜め方向の角でも高山・壁をすり抜けない。
- ワールド端でもプレイヤーが画面中央に留まり、マップ外が暗く表示される。
- 町とダンジョンへ入れ、出口から適切なワールド位置へ戻れる。切り替えが連続発火しない。
- 移動時に遭遇する一方、停止中、壁に押し付けている間、町、メニュー、遷移中には遭遇しない。
- 戦闘終了直後に再遭遇せず、勝利・逃走後は戦闘開始前と同じ探索位置へ戻る。
- 敵撃破時に反撃を受けず、逃走失敗時には反撃を受ける。連打で行動が重複しない。
- 敗北後は町で全回復し、回復地点でも全回復する。HPは0未満や最大HP超過にならない。
- メニューを開いている間は探索が停止し、閉じると再開する。決定キーの持ち越しで別画面の操作が発火しない。
- ウィンドウをリサイズしても主要UIが欠けず、日本語表示と選択中のコマンドが読める。

### 6.2 必要なロジック検証

乱数シードまたは乱数供給を検証用に固定できるようにし、確率に依存せず以下を確認する。

- 実移動距離の蓄積、安全距離の消費、端数の保持、無効マップでの抽選停止。
- マップ移動や戦闘復帰の座標変更が抽選距離に含まれず、メニュー開閉によって安全距離が復活しないこと。
- 攻撃による敵撃破、逃走成功・失敗、プレイヤー敗北の状態遷移。
- マップサイズとタイル配列の整合、出入口の移動先と安全な出現位置、開始地点から入口までの到達可能性。

Godotでの読み込み・スクリプト解析確認を行い、その後に実際の画面と入力で通し確認する。見た目やメニュー文言だけを検査する細かな自動テストは増やさない。

## 8. 成果物と実装時の留意点

- Godotエディタから実行できるプロジェクト一式。
- ワールド・町・ダンジョン各1つ、プレイヤーと敵2種類程度の独自仮素材。
- 起動方法、操作一覧、調整箇所、確認結果を記した文書。
- 既存のWindows書き出し設定は将来用として保持する。現段階では実行ファイルを生成・テストせず、Godotエディタからの実行手順を使用する。

実装着手時にGodot実行ファイルと日本語フォントを確認する。エクスポート環境・テンプレートの確認は将来Windowsビルドを作成する段階で行う。データ、描画、探索、戦闘の責務分離は行うが、初期版に不要な汎用RPGフレームワークは構築しない。

本計画に基づくゲーム本体、固定マップ3枚、敵2種、独自SVG、日本語フォントとライセンス、検証スクリプトを作成済み。過去のWindows実行ファイル作成・検証は履歴として扱い、現段階での再作成・再検証は行わない。

### 実装で確定した構成

- `scenes/main.tscn` が起動シーン。小規模なプロトタイプとして各画面の生成はGDScriptで行う。
- Mainの明示的な状態により入力・移動・戦闘演出を排他制御する。メニューでは探索の更新を呼ばず、通知の残り時間も保持する。
- 地形・敵・マップ・調整値は独自Resource、画面描画はGameUI、戦闘解決はBattleModelに分離した。
- Noto Sans JPを同梱し、FontVariationでウェイト500を指定。フォントライセンスも同梱した。
- 過去のWindows x86_64出力はゲームデータ埋め込みの `build/ARUPIGI.exe`。書き出し版のマップ・状態遷移も100項目の統合検証で確認した記録がある。これは現行ソースのWindowsビルドの検証済み状態を保証するものではなく、将来の作成時に改めて検証する。
- 当初の3.1〜4節にある数値・構成案の範囲内で実装し、第7節の除外範囲は追加していない。
