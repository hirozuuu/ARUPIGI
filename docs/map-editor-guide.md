# マップタイルエディタの使い方

Godot **4.6.x** で `project.godot` を開き、インポート終了後に上部の **マップ** を選びます。プラグインはプロジェクト設定で有効化済みです。表示されない場合は「プロジェクト → プロジェクト設定 → プラグイン」の **ARUPIGI マップ** を有効にしてください。

## 地形を編集する

1. 上部の一覧から野原・町・洞窟を選びます。「別のマップを開く」からプロジェクト内の別の `MapData` (`.tres`) も開けます。
2. 左のパレットで地形を選び、中央のキャンバスを左クリックして配置します。押したまま移動すると連続配置します。
3. 右クリック、または「消去」モードの左クリックで「消去後の下地」に戻します。初期の下地は野原・町が `plain`、洞窟が `floor` です。下地は上部で変更できます。
4. 必要に応じて倍率を50〜200%で変更します。スクロールバー、ホイール、中ボタンのドラッグで移動できます。
5. 「保存」を押して、ゲームを停止してから **F5** で起動し直します。

| 操作 | キー・ボタン |
| --- | --- |
| 地形を配置 | 左クリック・左ドラッグ |
| 下地へ戻す | 右クリック・右ドラッグ、または消去モードで左クリック |
| 元に戻す | 元に戻すボタン / Ctrl+Z |
| やり直す | やり直すボタン / Ctrl+Shift+Z |
| 保存 | 保存ボタン / Ctrl+S |
| 表示移動 | ホイール、スクロールバー、中ボタンのドラッグ |

ドラッグ1回をUndo1回で戻せます。キャンバス外でボタンを離した場合や、ウィンドウからフォーカスが離れた場合も、それまでの変更を1操作として確定します。追加した地形の文字対応も同時にUndo／Redoされます。同じ地形への上書きや範囲外への操作は履歴を増やしません。

ショートカットはマップ画面内にフォーカスがあるときだけ処理します。文字入力欄では、その入力欄の編集が優先されます。

## 目印と検証メッセージ

出入口と回復地点はゲームと同じ印、出現位置は青い **S** で表示します。地形を消去しても目印は残ります。黄色の枠はポインターのセルです。下部で座標、選択地形、下地、未保存状態を確認できます。

ストロークの確定、Undo／Redo、読み込み、保存時に検証します。「検証」から手動でも実行できます。

- **保存不可**：幅・高さ・行の長さ、未定義文字、地形テクスチャの欠落、1文字でない地形対応キー。形式不正のマップは描画できる範囲を表示し、編集を止めます。元Resourceを修正して再読み込みしてください。
- **要確認（保存可）**：出現位置・出入口・回復地点が範囲外、通行不可、孤立している場合など。問題のセル座標を表示します。出現位置と出入口の重なり、移動先の欠落、遭遇の敵候補も確認します。

通路を作っている途中でも形式が正しければ保存できます。ゲームに採用する前に警告も解消し、統合検証とゲーム内の移動確認を実施してください。

## 保存、切り替え、復旧

編集対象は `rows` と地形の文字対応 `terrains` です。サイズ、名前、出現位置、出入口、回復地点、遭遇設定、敵の外部Resource参照を保持します。元ファイルは保存まで変更しません。保存後も履歴が残り、Undo／Redoで最後に保存した状態へ戻れば「保存済み」に戻ります。

未保存でマップを切り替える場合や「再読み込み」を押した場合は、**保存して開く／破棄して開く／キャンセル** を選びます。新しいマップを開くと以前のマップの履歴は終了します。

保存時は元ファイルの内容を比較します。他のエディタやインスペクターがファイルを書き換えていた場合は上書きを止め、編集内容を保持します。「再読み込み」で外部の変更を取り込めますが、現在の編集を破棄する確認が必要です。外部変更との自動マージはありません。

保存は同じフォルダーの一時 `.tres` に書き込み、再読み込みでデータを照合し、元のUIDを保って置き換えます。書き込み権限などで失敗しても未保存状態と履歴を保持します。

Godot終了時には未保存のマップを通知し、エディタの保存操作とも連携します。さらに、確定した編集ごと、およびプラグイン終了時に次の復旧データをユーザーデータフォルダーへ保存します。

- `user://map_editor_recovery.tres`：未保存の作業マップ
- `user://map_editor_recovery.cfg`：元の保存先と外部変更比較用の情報

プラグインを無効化した後も、次回有効化時に復元を案内します。「後で」を選んだ場合は編集を保留し、マップ選択を操作すると再び復元の案内を表示します。「復元」で編集を続けるか、「復旧データを破棄」を選んでください。復元後も外部変更検出は有効です。元ファイルが削除された場合も復旧内容を表示できますが、その保存先へ自動的に新規作成はしません。

復旧は作業内容を戻す機能で、前回プロセスのUndo履歴は引き継ぎません。復旧ファイルの保存にも失敗した場合は画面とGodotのエラー出力に理由を表示します。復旧ファイルの場所はGodotの「プロジェクト → ユーザーデータフォルダーを開く」から確認できます。

## 素材を追加する

1. プロジェクトの `assets/art/` などに画像を追加し、Godotのインポート完了を待ちます。48×48を推奨し、他のサイズもセルに合わせて表示します。
2. ファイルシステムのResource作成から **TerrainData** を作り、`data/terrains/` 以下に `.tres` で保存します。サブフォルダーも走査対象です。
3. インスペクターで一意の `id`、`texture`、`walkable`（通行可否）を設定し、Resourceを保存します。
4. マップ画面で「素材一覧を更新」を押し、新しい地形を選んで配置・保存します。

マップが既に参照している地形は `data/terrains/` 外でもパレットに表示します。IDの重複・空欄やテクスチャ欠落のある素材は理由を表示し、配置を無効にします。

既存の文字キーを保ち、新素材に必要なキーだけを `a–z`、`A–Z`、`0–9` の順で割り当てます。同じResourceは既存キーを再利用します。空きがなければ配置前に中止します。キーを手で追加したりマップ全体を符号化し直したりする必要はありません。

新規マップの作成、サイズ変更、出入口などの編集、ゲームの `MAPS` への自動登録は対象外です。既存3マップはそのまま次回のゲーム起動で読み込まれます。

検証コマンドと今回の結果は [マップエディタ検証記録](map-editor-verification.md) を参照してください。
